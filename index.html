    Topic 1 of 8

    Naive Recursion and Repeated Subproblems

    • To make amount A, pick one coin c as the last coin. What is left is the smaller problem A − c.
    • Try every coin, solve each smaller problem by the same method, and keep the best.
    • The trouble: different branches ask for the same smaller amount again and again, and each repeat triggers its own whole tree of calls.
    f(0) = 0
    f(A) = 1 + min( f(A − c) ) for coins c ≤ A
    def f(a):
    if a == 0: return 0
    best = INF
    for c in coins:
        if c <= a:
            best = min(best, f(a - c) + 1)
    return best
    The number of calls roughly multiplies by the number of coins at every level, so it grows exponentially with the amount.

      Topic 2 of 8

      Dynamic Programming, Overlapping Subproblems, and Optimal Substructure

      • Dynamic programming solves each distinct subproblem once, stores the answer, and reuses it.
      • Overlapping subproblems: the same smaller problems come up many times. That is what the last slide counted.
      • Optimal substructure: the best answer for A is built from best answers to smaller amounts. If the best way to make A ends with coin c, the coins before it must be a best way to make A − c. Otherwise swap in a better one and you would beat the "best".
      • A problem needs both properties for DP to pay off. Without overlap you just have plain recursion. Without optimal substructure the stored answers can't be combined.
      Distinct subproblems here: only the amounts 0 … A. That is A + 1 answers to compute, not millions.

      Topic 3 of 8

      Minimum Coin Change Problem

      • Input: a list of coin values and a target amount A.
      • Rules: you have an unlimited supply of each coin, order does not matter, and the total must equal A exactly.
      • Output: the smallest number of coins that make A, or −1 if no combination works.
      coins = {1, 2, 5}, A = 11
      5 + 5 + 1 = 11 → answer 3

      Many combinations hit the target (eleven 1s, five 2s and a 1, and so on). We want the shortest one.

      Topic 4 of 8

      DP State, Recurrence, and Base Cases

      • State: what one subproblem is. Here, dp[a] = the fewest coins that make amount a. The final answer is dp[A].
      • Recurrence: how a state follows from smaller ones. Try each coin as the last coin.
      • Base case: the answer you know without computing. dp[0] = 0, because zero coins make zero.
      • No way to make it: if no coin leads to a reachable smaller amount, dp[a] = ∞.
      dp[0] = 0
      dp[a] = 1 + min( dp[a − c] ) for every coin c ≤ a
      dp[a] = ∞ if nothing works
      There are A + 1 states, one for each amount from 0 to A.

      Topic 5 of 8

      Memoization — Top-Down Dynamic Programming

      • Keep the recursive function from topic 1 and add a notebook (the memo).
      • Before computing f(a), look in the memo. If it is there, return it at once (a cache hit).
      • Otherwise compute it, store it, and return it. Each amount is computed only once.
      • It is called top-down because it starts from A and works down to the base case.
      memo = {}
def f(a):
    if a == 0: return 0
    if a in memo: return memo[a]     # hit
    best = INF
    for c in coins:
        if c <= a:
            best = min(best, f(a - c) + 1)
    memo[a] = best                   # store
    return best
      Watch for green hits in the log. Each one is a whole branch of the old recursion tree that never runs.

      Topic 6 of 8

      Tabulation — Bottom-Up Dynamic Programming

      • Skip the recursion. Fill a table dp[0..A] from the smallest amount upward.
      • When you reach dp[a], every dp[a − c] it needs is already filled.
      • Two loops: amounts 1…A, and for each amount, every coin.
      • No recursion means no call-stack limit, and usually a little less overhead than memoization.
      dp = [INF] * (A + 1)
dp[0] = 0
for a in range(1, A + 1):
    for c in coins:
        if c <= a:
            dp[a] = min(dp[a], dp[a - c] + 1)
return dp[A] if dp[A] != INF else -1
      Memoization asks "what do I need?" Tabulation says "I'll compute everything in order, so it is always ready."

      Topic 7 of 8

      Solution Reconstruction and Unreachable Amounts

      • Reconstruction: dp[A] gives only the count. To list the coins, also store parent[a], the coin that produced the best value for a.
      • Backtrack from A: take parent[A], move to A − parent[A], repeat until you reach 0.
      • Unreachable amounts: with coins {5, 10} you can never make 7. That cell stays ∞ and the answer is −1.
      • Guard the sentinel. Never add 1 to a "large number" that could overflow, and never reconstruct from an unreachable cell.
      if dp[a - c] + 1 < dp[a]:
    dp[a] = dp[a - c] + 1
    parent[a] = c

# rebuild
while a > 0:
    used.append(parent[a])
    a -= parent[a]

      Topic 8 of 8

      Time and Space Complexity; Greedy versus DP

      • Time: O(A · k) for k coins. There are A + 1 states and each tries k coins. Memoization and tabulation both match this.
      • Space: O(A) for the table. Memoization also uses recursion stack up to depth A. Reconstruction adds another O(A) array.
      • Naive recursion: exponential in A.
      • Greedy (take the biggest coin that fits, repeat) is fast, and it is correct for some coin systems such as 1, 5, 10, 25. For others it gives a wrong answer. DP is always correct.
      Classic counterexample: coins {1, 3, 4}, amount 6. Greedy takes 4 + 1 + 1 (3 coins). The best is 3 + 3 (2 coins).
